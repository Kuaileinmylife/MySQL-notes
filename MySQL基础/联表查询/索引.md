在关系型数据表中，索引是一种单独的，物理的对数据库表中一列或者多列的值进行排序的一种存储结构，它是表中一列或者多列值的集合，相应的指向表中物理标识这些值的数据页的逻辑指针清单
![[Pasted image 20260505160035.png|504]]
#### 索引的作用
1，保证数据的准确性
2，提高检索的速度
3，提供系统性能

#### 索引的类型
1，唯一索引(UNIQUE)：不可以出现相同的值，可以有NULL值
2，普通索引(INDEX)：允许出现相同的索引内容
3，主键索引(PRIMARY KEY)：不允许出现相同的值
4，全文索引(FULLTEXT INDEX)：可以针对值中的某个单词，但效率确实很低
5，组合索引：实际上是将多个字段建到一个索引里，列值的组合必须唯一

#### 索引的创建，查看，删除
```
-- 创建索引
ALTER TABLE 表名 ADD INDEX 索引名称 (字段值1，字段值2...);
-- 创建全文索引
ALTER TABLE 表名 ADD FULLTEXT 索引名称 (字段值1，字段值2...);
-- 查看索引
ALTER INDEX FROM 表名;
-- 删除索引
ALTER TABLE 表名 DROP INDEX 索引名称;
```
示例：
```
ALTER TABLE stu ADD INDEX sexIndex(sex);

SHOW INDEX FROM stu;

ALTER TABLE stu DROP INDEX sexIndex;
```

#### 索引的注意事项
1，虽然索引大大提高了查询速度，但也会降低更新表的速度，比如对表进行INSERT,UPDATE,DELETE操作，此时，数据库不仅要保存数据，还要保存一下索引文件
2，建立索引会占用磁盘空间的索引文件，如果索引创建过多(尤其是在字段多，数据量大的表上创建索引)，就会导致索引文件过大，这样反而会降低数据库性能。因此，索引要建立在经常进行查询操作的字段上
3，不要在列上进行运算(包括函数运算)，这会忽略索引的使用
4，不建议使用like操作，如果非用不可，注意正确使用方式，**like'%查询内容%'不会使用索引，而like'查询内容%'可以使用索引**
5，避免使用IS NULL, NOT IN, <>, !=, OR操作，这些操作都会忽略索引进行全表扫描
